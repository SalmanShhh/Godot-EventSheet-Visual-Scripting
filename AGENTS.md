# AGENTS.md

Deeper architecture map and standing contracts. `CLAUDE.md` is the operational front door
(commands, verification traps, house rules) - read it first; this file is the map behind it.
Measured figures (pack counts, ACE counts, suite size) live in `README.md` and are re-measured
there by tooling - this file deliberately avoids numbers that drift.

## Repo overview

GodotEventSheet (engine codename EventForge) is a Godot 4.x plugin (verified through **Godot 4.7
stable**) providing a Construct-style event-sheet editor and a compiler that emits plain, typed
GDScript. Sheets ARE `.gd` files: the round-trip is lossless and byte-identical, and any script
opens as a sheet. Three trees are COMPILER OUTPUT, regenerated by tools and drift-gated - never
hand-edit them: `eventsheet_addons/` (behavior packs, from `tools/pack_builders/`),
`demo/showcase/` (from `tools/build_examples.gd`), and `addons/eventsheet/help/` (the doc bundle,
from `tools/build_help_bundle.gd`).

## Architecture notes

- Plugin entry: `res://addons/eventforge/plugin.gd` (registers the workspace, export integrity,
  the debugger bridge and the attribute-drawers inspector plugin). Boot-path scripts never name
  heavy classes; the editor builds lazily (`_ensure_editor()`).
- Main workspace: `res://addons/eventsheet/editor/event_sheet_dock.gd` - the coordinator: tab and
  view lifecycle, the undo funnel, and a facade of thin delegates into ~40 `dock/*.gd` RefCounted
  helpers that reach back through a `_dock` reference. ALL sheet mutations go through
  `_perform_undoable_sheet_edit`, whose commit REPLACES resources with snapshot duplicates - never
  hold a row or resource reference across an edit; re-fetch from the live sheet.
- Custom-rendered row viewport: `res://addons/eventsheet/editor/event_sheet_viewport.gd` with
  `event_row_renderer.gd` - virtualized, no per-row Control widgets, fluid past 10,000 rows. Rows
  are `EventRowData` with spans, built by `interaction/viewport_row_builder.gd`.
- Compiler: `res://addons/eventforge/compiler/sheet_compiler.gd` (pipeline overview in its header).
  Emission is deterministic - no timestamps, no randomness - and output is plain code with zero
  plugin dependency (both are tested contracts).
- Builtin ACE vocabularies: per-module files in `res://addons/eventforge/registration/modules/`
  built via `ace_factory.gd` (module contract documented there); `builtin_aces.gd` auto-discovers
  them in sorted order with `helper_aces` forced last. The reverse-lifter does NOT go by registry
  order - it matches the most SPECIFIC template first, using registry order only to break ties.
  `helper_aces.gd` is the structured escape hatch, registered LAST and kept out of the reverse
  index except its statement catch-alls, admitted at the lowest specificity.
- Successor data (how a retired verb forwards): fields on `ACEDescriptor`
  (`.succeeded_by(...)` / `## @ace_succeeded_by(...)`), set at DESCRIPTOR CONSTRUCTION only,
  read through the one seam `registration/ace_successors.gd` (chains resolve to the end; cycles
  and unsound maps fail the pack gate in `tools/audit_addons.gd`). The project-level vocabulary
  version record is `eventforge/vocabulary_record.gd` - one committed line, never anything in a
  `.gd`.
- Importer/lifter (lossless GDScript pairing): `res://addons/eventforge/importer/` -
  `gdscript_importer.gd` + `ace_lifter.gd`, with the table engine beside them:
  `lift_table.gd` (an entry is data; byte round-trip tests are auto-generated per entry),
  `lift_example.gd` (derive an entry from a marked-up example line; refuses rather than guesses),
  `lift_grammar.gd` (shared capture fragments), and hand-written matcher files only for
  multi-statement families the table's header excludes. A line nothing claims stays an honest
  verbatim row (`RawCodeRow.lift_note`), never a mangled one.
- Reading layer (how an opened script becomes sentences): one grammar for typed and picked rows in
  `interaction/sentence_grammar.gd` (`EventSheetSentence`), with `viewport_lenses.gd`,
  `viewport_reading_rows.gd` and `viewport_row_builder.gd` beside it. Derived readings
  (`interaction/derived_calls.gd` / `derived_properties.gd` / `reading_shapes.gd`) turn any known
  class's calls and property writes into rows with zero authoring; curated tables outrank derived
  rows visibly and upgrade them in place. The scene index (`importer/scene_connections.gd`) is
  the ONE cached `.tscn` parse every scene-adjacent reader shares.
- Non-ACE row kinds (enums, signals, preloads, regions, pack kinds) dispatch through
  `EventSheetBlockRegistry` - see `docs/GUIDE-CUSTOM-BLOCKS.md`.
- The Doctor: `res://addons/eventforge/project_doctor.gd` plus per-domain `*_doctor.gd` section
  files, all registered through `EventSheets.register_doctor_check` and all reaching the same
  four runners (dock panel, headless CLI, CI, MCP). Findings surface as THE QUIET SHEET: the only
  in-sheet signal is the amber row state; words and fix doors live in the triage inbox and the
  selected row's help strip. Checks read EMITTED SCRIPTS (text) rather than sheet resources,
  because `.gd` is the default sheet format and `.tres` walks miss most projects.
- Completion: `res://addons/eventsheet/editor/autocomplete/` - `EventSheetCompletions` is the ONE
  candidate list (keyed by the parameter's own `hint`, cached per sheet, filtered per keystroke),
  one popup, and Quick Add reading a whole typed sentence. Public through
  `EventSheets.completions_for` / `register_completion_source` / `attach_completions`. There is
  no second completion engine.
- Parameter hints are load-bearing derivation keys: a hint like `file_path`
  (`registration/file_places.gd`, the one reading of `user://` vs `res://`) drives the place
  lead, completion, and the Doctor's fix tables - derived from descriptors, with literal tables
  demoted to override lists.
- The public API: `res://addons/eventsheet/api/eventsheets.gd` - all static; method shapes FREEZE
  once shipped, exactly like `ace_id`s. `EventSheets.migration_report()` is one such frozen shape.
- The Manual (in-editor docs): `res://addons/eventsheet/editor/doc/`, reading the shipped bundle
  in `res://addons/eventsheet/help/` - regenerated by `tools/build_help_bundle.gd`, byte-gated.
  Never hand-edit the bundle; any `CHANGELOG.md` edit requires a re-bake LAST.
- Editor localisation: `res://addons/eventsheet/translations/` - `TEMPLATE.csv` plus eight locale
  CSVs, source-string-keyed, hand-maintained in LOCKSTEP (same keys, same order, no empty cells;
  suite-gated). Every new user-facing string lands in all nine files.
- Dialogs build with `EventSheetPopupUI` helpers (`titled_card`, `panel_section`, `form_row`, the
  help strip family) - never raw flat controls.
- MCP server (AI tooling, policy-aware): `res://addons/eventsheet/mcp/mcp_server.gd`
- Theme resources: `res://addons/eventsheet/theme/*.gd`
- Test harness: `tests/run_tests.gd` auto-discovers `tests/*_test.gd` files exposing
  `static func run() -> bool`. The verdict is ONLY the literal `All tests passed.` /
  `Some tests failed.` line - never grep `[FAIL]` lines in either direction (probes print
  deliberate ones; crashed tests print none). `tools/run_tests_parallel.ps1` shards the suite
  (~6-9 min), names crashed tests, and stamps green verdicts per tree identity;
  `tools/test_daemon.ps1` answers a single test in under a second while iterating;
  `tools/test_report.gd` pre-investigates a red run. A tail segfault AFTER the verdict line is a
  known harmless teardown flake.
- The assertion vocabulary is ONE file, `tests/support.gd` (`EventSheetTestSupport`): `check` and
  `pins` print the suite's `[PASS]` / `[FAIL]` lines and the `expected:` / `actual:` pair the
  report tool parses, `pin_table` / `pin_value` are the quieter table form, and `compile_output` /
  `reopen` / `reemit` are the compile-and-round-trip trio. Extend it rather than adding a second
  reporter - the printed shapes are a contract, so a new shape needs the readers changed first.
- `tools/explain.gd -- <res://file.gd> <line>` says what one hand-written line became: the row the
  row builder makes of it (reopen, re-emit, source map) and then which reading layer would have
  claimed it. `EVENTFORGE_LIFT_ONLY=<entry ids>` narrows the lift-table harness to named entries,
  spelled after `EVENTFORGE_TEST_ONLY` so the two compose.
- Maintenance tools: `tools/` - pack builders in `tools/pack_builders/` (auto-registered by glob,
  no list to maintain; run by `build_sample_behaviors.gd`, which regenerates EVERY pack - prefer
  a single-builder throwaway script for one pack). A builder may hold its behaviour code as a
  folder of REAL `.gd` files under `tools/pack_builders/src/<pack>/` and assemble it with
  `Lib.pack_from_source` - a piece is a `#region` pair around top-level code or the body of a
  top-level `func`, so the code is highlighted, parse-checked and breakpointable instead of
  quoted and backslash-escaped. Those files spell their blank lines the EMITTER's way (one
  between members), which the style gate exempts by name and no one may re-space by hand; `build_examples.gd` (showcases, byte-stable);
  `audit_addons.gd` (pack drift + spelling + successor gates); `vocabulary_doc.gd`;
  `project_doctor.gd` (CLI shim); `verify_sheets.gd` (the four-contract repository gate: parses,
  round-trips, unique tokens, no unanswered migrations - read-only, exit-coded, wired into CI);
  `dump_registry.gd` (every descriptor in one sorted text form - the diff receipt for pack
  updates and the identity proof for vocabulary-touching refactors; `-- words` prints the WORDING
  as a second text, and a migrated module ships only when BOTH are byte-identical to the verbose
  form's - `prove_registry_identity.ps1 -Base <sha>` runs that gate through a detached worktree);
  `measure_ledger.ps1` (the maintainability campaign's ledger: hand-written GDScript and the shipped
  plugin, sized and diffed over pinned pathspecs, per area).

## EventSheet editor structure

- `EventSheetDock` owns toolbar, dialogs, ACE picker, variable workflows, context menus,
  undo/redo wiring, and theme load/reload - through its `dock/*.gd` delegates.
- `EventSheetViewport` owns hit-testing, stacked event layout, selection state, inline editing,
  drag/drop, zoom, and keyboard navigation.
- `EventRowRenderer` paints event/group/comment rows from `EventRowData` plus theme resources.
- `ACEPickerDialog` and `ACEParamsDialog` are the main extension points for new
  event/condition/action flows; node-scoped ACEs gain a `{target.}` prefix and an "On node"
  parameter at ship time (`_make_node_scoped_targetable`) - assert the post-transform form.

## Theme system notes

- `EventSheetEditorStyle` is the installable theme resource; `EventSheetEventStyle` covers
  structural tokens (sheet background, event shell, lanes, group/comment chrome, interaction
  fills); `EventSheetElementStyle` covers condition/action entry tokens.
- Designers edit `.tres` token resources directly (or through the Theme Editor dialog); the
  tokens are the single source of truth for the renderer.
- Theme docs: `docs/GUIDE-THEMING.md`, `docs/internal/SPEC-layout-alignment.md`.

## Standing contracts (read before changing the compiler, descriptors, or any public seam)

- **Parity**: generated GDScript is plain code - no plugin runtime, no indirection, performance
  identical to hand-written code (test-enforced).
- **Lossless**: opening a `.gd` as a sheet and saving untouched reproduces the file
  byte-identically. Every importer lift is gated by byte-exact re-emission; a lift that cannot
  reproduce its source must not fire - degrade to a verbatim block, never corrupt. Migrations,
  renames and re-mints are EDITS a human approved in a dialog, with receipts - never a side
  effect of opening or saving.
- **Frozen once shipped**: `ace_id`s, ACE `codegen_template`s, block `kind_id`s, `EventSheets`
  method shapes, and report shapes like `migration_report()`. Deprecate (successor data), never
  rename. Twins land BESIDE frozen rows.
- **Bake-at-apply**: templates bake onto rows when applied; `{uid}` is baked by the dock at apply
  time, never by the compiler; descriptor changes never rewrite sheets. Pack builders must
  pre-bake `{uid}` themselves.
- **ACEDefinitions are immutable after generation** - statically cached and shared across every
  tab for the session. Bake changes into row copies only; successor data is construction-time.
- **Lazy-init flags are only set by the function that does the full initialization.**
- **The quiet sheet**: a finding never renders a block, icon, or inline text in the sheet - amber
  row state only, words in the inbox and the selected row's strip. The one exception is a
  file-level blocking state (an unresolved merge opens read-only with a head banner).
- **Policy gates, never bytes**: composition ProjectSettings only allow/warn/error.
- Style: tabs everywhere, `class_name` before `extends`, two blank lines around functions,
  snake_case - suite-enforced (`tests/style_guide_test.gd`). Compiler OUTPUT keeps single-blank
  formatting by design. No em-dashes anywhere in repo text (" - "). No absolute personal paths
  (suite-swept). Comments are self-contained - no "see docs/X.md" pointers in code.

## Current known gaps

- The pack-update backup ring has no per-file restore door in the editor (the ring is a folder of
  files; the Restore menu restores the sheet in front of you). The applied receipt names the ring
  folder.
- The Doctor's rename/migration sweep over `.gd` sheets reads a bounded sample per run and says
  so in its own verdict line - whole-project certainty comes from `tools/verify_sheets.gd`.
- No shipped verb pair carries a successor address yet: the seam, the gates and the harness are
  live, and the guide records why the first candidate pair was withdrawn (its parameters do not
  mean the same thing). Add an address only for verbs that truly map.
- The theme package manifest is documentation/template only; it is not auto-imported yet.
- UI screenshots require a NON-headless Godot run: the `tools/render_*.gd` harnesses generate
  real editor-UI PNGs (headless runs cannot render); many are committed because their UI will
  move again.

## Guidance for future LLM-assisted work

- Keep the custom-rendered viewport/event-row approach; do not replace it with per-row Control
  widgets (the Control-widget prototypes were removed - they could not scale).
- Prefer surgical changes in `EventSheetDock`, `EventSheetViewport`, and theme resources over
  large rewrites; preserve undo/redo and right-click selection preservation.
- Trust only the suite's verdict line, run through the runners in `CLAUDE.md` - its
  "Verifying results" section lists the traps that bite here (silent failures, indented FAIL
  lines, cold-vs-warm cache leaks, half-way float pins, unsorted walks).
- New behaviors are pack builders, never standalone addons; new user-facing strings land in all
  nine translation CSVs in lockstep; every feature lands with tests, a CHANGELOG entry, and (for
  UI) a rendered preview.
- Extend the existing seam rather than minting a parallel one: the completion seam, the Doctor
  section register, the lift table, the block registry, the successor map, and the popup helpers
  each exist so the next feature is an entry, not a subsystem.
